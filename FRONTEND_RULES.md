 * Flat, solid colors: Rely on flat, solid color palettes rather than distracting color transitions. This ensures visual stability and keeps the user focused entirely on the core functionality rather than flashy aesthetics.
 * System-native icons: Utilize system-default icons (like Material Design or SF Symbols) or clear text labels. This prioritizes universal recognition and accessibility over forcing a trendy, custom iconography set onto the user.
 * Off-white backgrounds: Avoid stark #FFFFFF backgrounds, which can cause harsh glare and eye strain on mobile displays. Instead, use soft off-whites or light grays to improve long-session readability and comfort.
 * Strict brand colors: Stick to a limited color palette using your primary brand colors or simple monochromatic shades. Avoid multi-colored spectrums that can make the mobile interface look chaotic and unorganized.
 * Flat hierarchy: Remove all exaggerated drop shadows to embrace a strictly flat design language. Use simple, high-contrast borders or subtle background color changes to define UI layers without artificial depth.
 * Vertical lists: Display information in straightforward, easily scannable vertical lists rather than cramped horizontal carousels. This respects the natural vertical scrolling behavior of mobile users and prevents screen clutter.
 * Professional iconography: Maintain a professional tone by removing emojis from the user interface and copywriting entirely. Rely on universally understood, minimalist graphics to convey meaning without relying on casual internet slang.
 * Opaque backgrounds: Use completely opaque, solid backgrounds for modals, menus, and bottom sheets. This ensures maximum legibility and prevents underlying content from creating visual noise or distraction during navigation.
 * Standard punctuation: Write clear, concise mobile copy using standard punctuation and shorter sentences. Avoid using dramatic em dashes, which can unnecessarily interrupt the natural reading flow on restricted screen sizes.
 * Native system fonts: Exclusively rely on native OS fonts like San Francisco for iOS or Roboto for Android. This guarantees optimal rendering, perfect accessibility, and a seamless native feel for the user.
 * Clear typographic hierarchy: Differentiate content using bold headings or subtle, full-width background shading instead of thin colored stripes. This ensures important information is not easily missed during quick, one-handed mobile scrolling.
 * Authentic reviews only: Only display genuine, verified user feedback, or omit the review section entirely from your onboarding. Building actual trust is far more valuable than padding the UI with artificial, placeholder social proof.
 * Predictable linear layouts: Organize dashboard elements into standard, predictable linear layouts or uniform grids. Avoid asymmetrical designs, which can confuse users trying to quickly locate specific touch targets or metrics.
 * Standard UI components: Present technical settings or code snippets using standard text views and native mobile UI components. Avoid faux-terminal styling, as it creates unnecessary visual friction and sacrifices native accessibility features.
 * Literal copywriting: Describe your app's functionality with straightforward, literal, and highly descriptive language. Avoid clever but vague marketing riddles so the user instantly understands the exact utility being provided.
 * Neutral bullet points: Use standard bullet points or numbered lists to describe premium features neutrally and clearly. Avoid universally positive green checkmarks that can feel overly aggressive or strictly promotional in a paywall.
 * Transparent pricing: Offer a single, transparent pricing model or a straightforward free/premium binary split. Avoid the psychological manipulation of artificial three-tier systems designed to push users toward a middle option.
 * Authentic UI screenshots: Showcase genuine, functional screenshots and realistic screen recordings of the actual app in use. Users need to see exactly how the interface works and looks before committing to a download.
 * Standard corner radius: Use sharp 90-degree corners or the exact default border radius prescribed by iOS and Android guidelines. Avoid universally smooth, rounded edges that homogenize the design and ignore platform-specific standards.
 * Neutral dark mode: Implement a true dark mode using neutral dark grays and high-contrast primary colors for legibility. Avoid the trendy glowing purple-and-black aesthetic, which can feel alienating or overly stylized for standard utilities.
 * Graceful skeleton screens: Design precise, structural skeleton loaders for all network requests to smooth out loading times. This manages user expectations perfectly and prevents jarring visual layout shifts when data finally arrives.
 * Clean backgrounds: Keep background layers completely clean, solid, and free of unnecessary artistic elements. Avoid blurred radial orbs that add pointless visual noise and distract from the interactive foreground targets.
 * Unpatterned layouts: Rely on plain, unpatterned backgrounds to maintain absolute clarity and focus on the foreground content. Avoid faux-technical dot grids that add zero functional value to the mobile user experience.
 * Descriptive action icons: Indicate automated or complex functions with descriptive text or universally standard icons like gears. Avoid the ambiguous four-point sparkle that fails to explain what the feature actually does under the hood.
 * Static affordances: Use clear, static button designs and standard structural affordances to guide the user's flow. Avoid animated, looping arrows that act as distracting, desperate pleas for the user's attention.
 * Accessible Terms of Service: Ensure your Terms of Service are clearly linked, easy to read, and required during the onboarding flow. Prioritizing legal transparency builds long-term user trust and protects your application properly.
 * Prominent privacy controls: Make privacy policies and data management controls highly visible directly within the main settings menu. Hiding legal disclaimers for the sake of a minimalist aesthetic is dangerous and erodes user confidence.
 * Native touch feedback: Rely entirely on the native ripple effects and standard touch feedback built into the mobile OS. Avoid custom scaling or color-shifting animations that can feel sluggish, heavy, or non-standard on mobile devices.
 * Accessible contrast palettes: Choose balanced, high-contrast colors that easily pass WCAG accessibility standards for text readability. Avoid harsh, fluorescent neon accents that cause eye fatigue and clash with native OS environments.
 * Purposeful color hierarchy: Use strong, purposeful brand colors to establish a clear visual hierarchy and distinct interactive elements. Avoid washing out the interface with desaturated pastels that make crucial touch targets hard to distinguish.
